\chapter{Theoretical Background\label{cha:chapter2}}

The engineering contributions described in Chapters~4 through~8 all rely on a small number of theoretical constructs that happen to have been discovered decades earlier: recursive Bayesian estimation, sample-based approximation of posteriors, kinematics of constrained wheeled vehicles, distributed mutual exclusion, and statistical pattern classification. None are specific to warehouse logistics, and none were invented for the purposes of this thesis; rather, this thesis applies a particular narrow slice of each to a three-robot inspection fleet. It is then up to Chapter~3 to review related work that extends, critiques, or challenges those foundational ideas in the limited ways relevant to this thesis (task allocation, deadlock avoidance, fault-tolerant coordination, and edge-mounted vision). The present chapter serves a narrower purpose: to describe the mathematical machinery behind each of these areas, independent of any particular application, so that later chapters can refer to the established notations and results directly.

\section{Recursive Bayesian State Estimation and the Markov Assumption}

All practical approaches to mobile robot localization, including the most basic Kalman filter and the most sophisticated particle-filter SLAM, are based on one core idea: recursive Bayesian estimation. In fact, one recent survey of the literature on both classical and learning-based approaches groups estimators according to their representation of the belief distribution, while holding the general framework of recursive conditioning on the same sequence of control inputs and sensor outputs \cite{ebner2026robot}. Let us then formalize this estimation framework.

Let $x_t$ be the state of a vehicle or robot moving in some space; the subscript $t$ denotes discrete time steps, and for the purposes of localization in a warehouse, $x_t$ is likely to be the robot's pose on $\mathrm{SE}(2)$ or $\mathrm{SE}(3)$. The robot is not aware of its state, but can build a probabilistic model of it based on a known or learned kinematic model, previous control inputs $u_{1:t}$, and sensor readings $z_{1:t}$. More formally, we are talking about the posterior distribution of the state given the inputs and outputs:
\begin{equation}
\mathrm{Bel}(x_t) = p(x_t \mid z_{1:t}, u_{1:t}) \label{eq:belief_definition}
\end{equation}

The challenge of state estimation is to approximate this distribution recursively, given its prohibitively large dimensionality. The solution is to assume that the system is Markovian, i.e., that the previous state contains all the information needed to determine the current state, given the control input:
\begin{equation}
p(x_t \mid x_{0:t-1}, z_{1:t-1}, u_{1:t}) = p(x_t \mid x_{t-1}, u_t) \label{eq:markov_motion}
\end{equation}

Similarly, the current observation is conditionally independent of all previous inputs and observations:
\begin{equation}
p(z_t \mid x_{0:t}, z_{1:t-1}, u_{1:t}) = p(z_t \mid x_t) \label{eq:markov_observation}
\end{equation}

In other words, Equation~\eqref{eq:markov_motion} defines the motion model and Equation~\eqref{eq:markov_observation} defines the observation model. Neither is true of a real-world robot, as wheel slippage depends on the surface roughness traversed and a laser rangefinder's output depends on the amount of dust on its protective window, but both are convenient approximations that allow the computation of meaningful posteriors. Given the Markov assumption, the joint distribution $p(x_{1:t} \mid z_{1:t}, u_{1:t})$ factors into a product of $p(x_t \mid x_{t-1}, u_t, z_t)$ and $p(z_t \mid x_t, u_t)$. The recursion proceeds in two steps: first, the prediction step, in which the previous posterior is projected forward using the motion model,
\begin{equation}
\overline{\mathrm{Bel}}(x_t) = \int p(x_t \mid x_{t-1}, u_t)\, \mathrm{Bel}(x_{t-1}) \, dx_{t-1} \label{eq:bayes_prediction}
\end{equation}

followed by the correction step, in which the observation is used to update the belief,
\begin{equation}
\mathrm{Bel}(x_t) = \eta \, p(z_t \mid x_t) \, \overline{\mathrm{Bel}}(x_t) \label{eq:bayes_correction}
\end{equation}

where $\eta$ is a normalization constant. Together, Equations~\eqref{eq:bayes_prediction} and~\eqref{eq:bayes_correction} define the recursive Bayesian estimator, also known as the Bayes filter. Any specific algorithm for localization, including the popular extended Kalman filter (EKF) or the grid-based Markov localization, is a Bayes filter that uses a particular representation for the belief distribution. For example, the EKF represents it as a Gaussian density function, which allows for inexpensive recursive updates but restricts the posterior to be unimodal. A sample-based representation, on the other hand, allows for greater flexibility at the cost of approximating the recursion using importance sampling. That state representation is discussed in more detail in Section~\ref{sec:mcl_theory}, where it is used in the localization algorithm from Chapter~6.

\section{Monte Carlo Localization: Particle Filter Theory and the Kidnapped-Robot Problem}
\label{sec:mcl_theory}

Grid-based (discretized) Markov localization performs exact inference in the sense of Equations~\eqref{eq:bayes_prediction}--\eqref{eq:bayes_correction} over a finite state grid, but the number of grid cells needed to achieve angular and spatial resolution necessary for navigating an environment is too large to be practical for anything beyond a toy setting on embedded hardware. Monte Carlo (or particle filter) localization addresses this issue by approximating the belief distribution as a set of $M$ weighted particles,
\begin{equation}
\mathcal{X}_t = \left\{ x_t^{[1]}, w_t^{[1]} \right\}, \dots, \left\{ x_t^{[M]}, w_t^{[M]} \right\} \label{eq:particle_set_definition}
\end{equation}

each representing an hypothesis about the state of the robot, represented by the tuple $(x, y, \theta)$, with the set of weights $w_t^{[m]}$:
\begin{equation}
\mathrm{Bel}(x_t) \approx \sum_{m=1}^{M} w_t^{[m]} \, \delta\!\left(x_t - x_t^{[m]}\right) \label{eq:particle_belief_approximation}
\end{equation}

The algorithm, first presented by Dellaert et al.\ as Monte Carlo localization \cite{dellaert1999monte} and later extended and formalized by Thrun et al.\ \cite{thrun2001robust}, proceeds in 3 stages for each time step:

\begin{enumerate}
    \item \textbf{Sampling.} For each particle $x_{t-1}^{[m]}$, a new pose $\bar{x}_t^{[m]}$ is sampled from a proposal distribution $p(x_t \mid x_{t-1}^{[m]}, u_t)$ that embodies the noise characteristics of the drive train.
    \item \textbf{Weighting.} Each particle's weight $w_t^{[m]}$ is updated according to the likelihood of the measurement $z_t$ given the particle's hypothesis, $w_t^{[m]} \propto p(z_t \mid \bar{x}_t^{[m]})$.
    \item \textbf{Resampling.} The particle set is re-sampled with replacement according to the weights, stochastically discarding low weight particles and re-inflating high weight particles -- this is the mechanism that allows the algorithm to avoid tracking impossible states, at the cost of performance degradation in the case of ``particle depletion'', when the variance of the importance sampling distribution is low enough that the algorithm falls into a degenerate state of near-zero diversity in the particle set.
\end{enumerate}

The choice of the number of particles $M$ is likewise a trade-off between performance and computational budget -- adaptive allocation schemes such as KLD-sampling can be used to bound the KL-divergence between the true posterior and the approximate posterior represented by a set of particles, allowing for variable $M$ depending on the concentration of the belief density \cite{fox2003kld}. This is critical for the application in resource-constrained settings such as on a microcontroller -- a fixed-size particle filter that is large enough to perform global localization only wastes most of its compute budget on maintaining a very tight covariance ellipsoid most of the time. In contrast to the families of filters described in Section~2.1, the particle filter's ability to represent multi-modal beliefs is critical and must be retained, for instance, when the robot is re-localizing after a ``kidnapping''.

A kidnapped robot is one that has been moved to an arbitrary pose without its knowledge -- this scenario often arises in practice due to loss of traction on a slippery surface, and in robotics competitions such as RoboCup, referees may occasionally move a robot to a different location on the field for disciplinary reasons. Any ``re-localization'' algorithm that has converged to a single mode will fail catastrophically in the case of a kidnapping, since the information about the other location modes has been discarded when collapsing the covariance matrix. In this context, the particle filter's ability to maintain multiple hypotheses about the robot's location is its defining advantage, allowing it to recover from such situations if there is a sufficiently large enough population of particles with non-zero weight representing the kidnapped pose. In practice, this is often implemented by maintaining a certain number of particles with uniformly randomized poses across free space in the particle set (often referred to as ``resampling''), and/or relaxing the effective sample size threshold for resampling. The decrease in localization accuracy during this phase is a tolerable price to pay for avoiding a catastrophic failure in the case of a kidnapping. This trade-off is also a primary consideration in the decision to gate localization uncertainty against a certain threshold and ``restart'' the localization process with more aggressive recovery heuristics if the threshold is exceeded repeatedly, as described in detail in Chapter~6. The recursive execution cycle of Monte Carlo localization—incorporating kinematic sampling, measurement weighting, adaptive resampling, and uncertainty-gated particle dispersion for kidnapped robot recovery—is schematically illustrated in Figure~\ref{fig:ch2_mcl_cycle}.

\section{Non-Holonomic Kinematics and SE(2) Rigid-Body Transformation Theory}

The state that the estimators of Sections~2.1--2.2 reason about actually lives, for a ground vehicle constrained to the plane of a warehouse floor, in the special Euclidean group $\mathrm{SE}(2)$: the space of rigid-body poses $(x, y, \psi)$ comprising a planar translation and a vertical rotation. The composition of two such poses requires more than simple addition of coordinates since the rotational component of the first must be applied to the translational component of the second, which can be represented by the homogeneous transformation matrix
\begin{equation}
\mathbf{T} = \begin{bmatrix} \cos\psi & -\sin\psi & x \\ \sin\psi & \cos\psi & y \\ 0 & 0 & 1 \end{bmatrix} \in \mathrm{SE}(2) \label{eq:se2_homogeneous_general}
\end{equation}

which accumulates rotation and translation into a $3 \times 3$ operator, so that projecting a point expressed in the local frame of reference into the global frame becomes a matter of simply multiplying its coordinate vector by the appropriate matrix. The same general approach, with its variations for composing multiple transformations in a chain, appears throughout Chapter~5 in a number of different contexts, and is not specific to any particular estimator as implemented in this thesis's simulation framework of choice (Campion et al.\ \cite{campion1996structural} states it as the standard representation for the same reason).

Not all $\mathrm{SE}(2)$ trajectories are physically accessible to a robot platform of a given mechanical design, however. The classic differential-drive mobile robot, of which this thesis's primary simulated vehicle is an example, cannot generate sideways motion; the wheels are mounted to a common axle, and no rotational torque applied to either can result in a linear velocity component of the chassis perpendicular to that axle. This places the mechanical platform on the same footing theoretically as a unicycle or a car, as a non-holonomic system whose kinematic constraint cannot be integrated to yield a restriction on its configuration space alone. Expressed as a Pfaffian constraint, the instantaneous velocity of the chassis center-of-mass frame (which is always coincident with the robot's center in this model) satisfies the condition
\begin{equation}
\dot{x} \sin\psi - \dot{y} \cos\psi = 0 \label{eq:pfaffian_constraint_general}
\end{equation}

that its translational component is aligned with its rotational component, $\psi$. The work of Campion, Bastin, and D'Andrea-Novel \cite{campion1996structural} classifies wheeled mobile robots according to a generic mobility/steering capability indicator shared across vehicle types with different actuator arrangements, and subsumes differential drive (two standard wheels on an axle), tricycle, and car forms under a single set of equations by noting the location of the non-holonomic constraint, Equation~\eqref{eq:pfaffian_constraint_general}, in each. The forward kinematic mapping from the angular velocities of the two wheels to the chassis velocity then follows as
\begin{equation}
\begin{bmatrix} \dot{x} \\ \dot{y} \\ \dot{\psi} \end{bmatrix} = \underbrace{\begin{bmatrix} \frac{r}{2}\cos\psi & \frac{r}{2}\cos\psi \\ \frac{r}{2}\sin\psi & \frac{r}{2}\sin\psi \\ \frac{r}{b} & -\frac{r}{b} \end{bmatrix}}_{\mathbf{J}(\psi)} \begin{bmatrix} \dot{\theta}_R \\ \dot{\theta}_L \end{bmatrix} \label{eq:differential_drive_jacobian_general}
\end{equation}

with wheel radius $r$ and track distance $b$ between the two wheels as the only additional parameters.

A more recent descriptor of generalized wheel mounting schemes \cite{pantoja2026generalized} proposes a unified Jacobian expression for a variety of wheeled robot forms, including Ackermann, tricycle, and omnidirectional, in terms of per-wheel position and rolling direction parameters. The same Jacobian specialization would generate the expressions for the differential drive as in Equation~\eqref{eq:differential_drive_jacobian_general} by plugging in the corresponding descriptors for two standard wheels as the only actuators, but no specific derivation is given for this particular combination. The Jacobian, $\mathbf{J}(\psi)$, is a $3 \times 2$ matrix in the case of the differential drive, which renders it non-invertible; one must take a left pseudo-inverse to recover the wheel velocities required to achieve a given chassis velocity, or vice versa. The fact that the platform only has two independent actuators, the wheels, which generate three-dimensional motion in the chassis frame (up to rotation about the vertical axis) is the reason for the non-holonomicity of the constraints mentioned previously in Equation~\eqref{eq:pfaffian_constraint_general}. This kinematic formulation underlies all the motion models used in Chapter~5, from the definition of the corridor approach geometry to the discussion of the visual tracking controller. It is treated separately, outside the specific details of the multi-robot configuration used in this thesis, because none of these details are needed for any of the considerations of this section.

\section{Hierarchical Motion Planning: Global--Local Decomposition and Costmap Theory}

While a mobile robot's onboard processor may be up for the task, finding a single, dynamically-feasible, collision-free trajectory from start to finish that is optimal in any reasonable metric is, in general and for any realistic environment, simply too computationally taxing to be performed within a mission's timeframe. As such, it is common practice to decompose the motion-planning problem into two distinct but intertwined subproblems: a global planner that performs coarse reasoning over the whole map to produce a rough trajectory that avoids known obstacles; and a local planner that operates at a finer scale and higher frequency to refine the coarse trajectory into dynamically-feasible commands and avoid additional, close-range obstacles. A recent survey of the literature on the planning algorithms for mobile robots notes the two-tier structure as the standard reference point: ``All other methods are compared to this basic approach, including more modern planning algorithms such as sampling-based, learning-based planning, and planners that use reinforcement learning to unify the problem'' \cite{dong2023review}.

At the higher level, the global planner is typically tasked with a graph-search problem over a discretized representation of the workspace. Cells of an occupancy grid or nodes in a topological graph are linked by edges that encode a distance or navigability cost, and most methods for this stage, including the dominant A* algorithm and its numerous successors, amount to a best-first search that uses an admissible heuristic to ``produce an optimal path whenever the estimated cost to reach a goal node is never larger than the actual cost'' \cite{hart1968formal}. Since the global planner reasons about the environment in a static way, only occasionally updating its internal representation in response to the local planner's failures, it can afford to operate on a lower frequency: ``the global planner only replans when the local planner fails, or only at the beginning of a mission, or only a fixed number of times throughout a mission''. In contrast, the local planner must operate in real-time alongside the robot's low-level controllers, typically refreshed every few tenths of a second, and account for additional obstacles not present in the global map. One method, the Dynamic Window Approach, reformulates the local planning problem in terms of linear and angular velocity rather than position: ``it searches over a set of candidate velocities that a robot might select, discarding any that would cause the robot to collide with an observed obstacle, and then picks the velocity with the best trade-off between progress toward the goal, linear velocity, and clearance'' \cite{fox1997dynamic}. The local planner is thus significantly more involved than the path-tracking controllers that have been discussed in Section~2.5: while those only concern themselves with following a previously-determined trajectory, the local planner must generate a trajectory dynamically while taking its own control constraints into account. A unified system for motion planning would therefore consist of a global planner, selecting a high-level path, followed by a local planner, generating low-level control commands in real-time while avoiding close-range obstacles.

In practice, both the local and global planners are aware of the same concept of a costmap: a grid of values that encode the traversability of the environment, where the 0/1 free/occupied encoding of an occupancy grid is replaced with a continuous value that decays exponentially with proximity to obstacles. The local and global planners require this information at different update frequencies and from varying receptive fields -- a local planner's costmap spans a small area around the robot and is refreshed at the same rate as the local planner, while the global planner's costmap covers the whole environment but is only updated intermittently. As such, a common implementation detail, formalized by the layered costmaps framework, is that the individual values in the costmap are stored as a sum of multiple layers that are only combined when a planner queries the value of a particular grid cell. This allows the same costmap to be used by both the local and global planners without interference: ``the static layer, which is derived from the underlying map, and the obstacle layer, which records the location of recently observed obstacles, are combined with an inflation layer to form a costmap that encodes both obstacle avoidance and robot-specific constraints'' \cite{lu2014layered}.

The two-tier approach is not without its complications. Planners using this method often find themselves in situations that require recovery behaviors due to inconsistencies between the local and global planners. ``The underlying reason for these difficulties is that the global and local planners see slightly different world models: the cell contents vary depending on which planner is querying the costmap,'' and the difference in local perception between the two is what creates the need for the recovery behaviors in Chapter~6.

\section{Pursuit-Based Local Path-Tracking Control Theory}

A fundamentally differerent class of local controllers addresses a significantly more constrained problem than that addressed by the velocity-space search method of Section~2.4: rather than searching for admissible motions at every control timestep, a path-tracking controller assumes that the global layer has already provided a reference trajectory, and asks a purely geometric question: given the relative position and orientation of the robot to the reference trajectory, what instantaneous curvature should the chassis follow in order to return to the reference trajectory? The oldest and simplest answer to this question is provided by Pure Pursuit algorithm first described in a CMU technical report implementing it on the Terragator and the Navlab platforms; since then, it has been adapted with few modifications to a variety of different classes of vehicles, including differential-drive, Ackermann cars, and legged-robots \cite{coulter1992implementation}.

The geometric considerations which lead to the algorithm are nearly as simple: pick a distance $L_d$ ahead which the robot should try to drive towards, find where along the reference trajectory this point is approximately located in the robot frame of reference, and find a circular arc passing through both the robot position and the lookahead point and tangential to the robot chassis at the robot position. If the angle between the robot orientation and the line of sight to the lookahead point is $\alpha$, elementary geometry gives the relation between the turning radius of this arc and the distance to the lookahead point:
\begin{equation}
\kappa = \frac{2 \sin \alpha}{L_d} \label{eq:pure_pursuit_curvature}
\end{equation}

which the low-level controller then converts to an angular velocity command using $\omega = \kappa v$, with $v$ being the commanded linear velocity of the robot. In essence, a proportional controller is applied to the cross-track error at the lookahead distance, with the gain determined by the sine of the angle $\alpha$; this makes the lookahead distance also a tunable parameter for the control law, as a larger $L_d$ decreases the effective gain. This tuning is necessary, since too small a value of $L_d$ leads to excessive and rapid corrections to cross-track errors, which result in undesirable oscillatory heading adjustments for the same error on a noisy or position-estimation error prone platform. These oscillations are especially pronounced at low forward speeds, since $\alpha$ will be large for a fixed cross track error, resulting in a correspondingly large turn. Conversely, too large a value of $L_d$ leads to an undesirable ``drifting'' effect, where the robot begins to turn in anticipation of upcoming turns, leading to the robot driving at a lower radius than the reference trajectory; the amount of this ``corner-cutting'' effect is proportional to the value of $L_d$ and the curvature of the reference trajectory at the point of closest approach. These effects are discussed in detail in the original report, which evaluates tracking performance on the CMU platforms using different $L_d$ values spanning an order of magnitude \cite{coulter1992implementation}.

It is simplest to address this issue by making the ``lookahead distance'' a function of the forward speed of the robot, so that the product of forward velocity and ``response time'' stays roughly constant; methods such as variable lookahead distance are common enough that they can be considered standard practice in path-tracking control design. More recent approaches also consider varying the effective lookahead distance based on the local costmap (see Section~2.4) as well as the instantaneous curvature of the reference trajectory, slowing down the robot in anticipation of sharp turns or when following a reference trajectory close to static obstacles before applying Equation~\eqref{eq:pure_pursuit_curvature}. These modifications to Pure Pursuit are collectively referred to as Regulated Pure Pursuit, and have seen adoption in the ROS~2 navigation stack as a reference implementation for path tracking \cite{macenski2023regulated}. The major modification this approach makes to the standard geometric path-tracking controller described in this section is similar in spirit to the modifications made to the velocity-space search method of Section~2.4: velocity is determined not purely by the lookahead-distance based cost function, but also by a separate metric (the local costmap) which informs the controller of nearby obstacles; in essence, the two approaches to local path planning are unified in the Regulated Pure Pursuit framework by modifying the velocity command used to execute Equation~\eqref{eq:pure_pursuit_curvature}, which determines the instantaneous turn radius, in order to account for the robot's ability to stop in time to avoid collisions.

\section{Distributed Mutual Exclusion and Deadlock Theory in Multi-Agent Systems}

When multiple independent processes contend for a resource that cannot be safely shared - a database row, a communication channel, or, starting as of Chapter~5, a narrow passageway between shelves - ensuring that no more than one process controls it at a given moment is the mutual exclusion problem, which precedes distributed robotics by several decades. Establishing an ordering of events when requesting it between processes that share no common clock is also non-trivial: Lamport's logical clock construction provides a total ordering of events via a scalar timestamp $C(e)$ for every event $e$, compatible with the happens-before relation $\rightarrow$, i.e. the smallest relation satisfying
\begin{equation}
e_1 \rightarrow e_2 \implies C(e_1) < C(e_2) \label{eq:lamport_clock_condition}
\end{equation}

for any two events $e_1, e_2$ on the same process, or connected by a message send/receive \cite{lamport1978time}. Note that $\rightarrow$ is not necessarily a total order: two events on different processes with no communication between them are incomparable, hence the name partial order. It is this comparability that makes distributed coordination more challenging than the single-process case: when a process receives a request from another, it cannot determine whether the requesting process's clock was ahead or behind its own physical time, hence whether it should prioritize responding before or after processing its own requests, beyond deferring to the ordering of Lamport timestamps, which only encode logical causality.

There are two broad classes of algorithm that use such logical timestamps to implement mutual exclusion; permission-based algorithms, of which the priority-based tie-breaking rule used in Chapter~5 is an example, require each process to obtain permission from all others before entering the critical section \cite{ricart1981optimal}, while token-based approaches provide a single process with exclusive privileges to access the resource and arbitrate between others, with Suzuki and Kasami's broadcast algorithm requiring $2(N-1)$ messages per permission request in the former class versus a maximum of $N$ per request for the latter at the cost of additional state management to avoid stale requests interfering with current ones \cite{suzuki1985distributed}. In either case, the request itself remains serialized - a tolerable overhead for a short-lived critical section, but a significant bottleneck for a resource like a warehouse aisle a robot has to traverse to access, which is the use case Chapter~5 is concerned with.

Mutual exclusion is only part of the story: granting exclusive access to multiple resources at once can cause deadlocks, where all contending processes wait indefinitely for another to release the resource. Coffman et al.\ note that for reusable resources (as opposed to consumable ones), deadlocks form if and only if all four of the following conditions are met: mutual exclusion (each resource is allocated to exactly one process), hold-and-wait (each process holds at least one resource while waiting for another), no preemption (resources cannot be forcibly taken away), and a circular wait condition (each process is waiting for a resource held by the next process in a circular chain) \cite{coffman1971system}. Deadlock avoidance schemes generally target one of these conditions, as breaking any one of the four suffices to prevent deadlocks; mutual exclusion and hold-and-wait are typically required for normal operation, preemption is dangerous for a moving robot, while circular waits are easily broken by denying any single process further resource requests until its current ones are released. Multi-robot deadlocks present a variation of the classical deadlock problem, and have received some attention from the research community: Zhou et al.\ examine higher-level deadlocks that occur in multi-robot systems when three or more robots are deadlocked within a single circular wait and propose a distributed detection algorithm requiring no central authority \cite{zhou2020distributed}, while Grover et al.\ consider the geometric and control-theoretic conditions under which reactive, locally optimal planners for individual robots can fail to avoid collisions altogether and fall into a deadlock \cite{grover2023deadlock}. What all of the above do not examine is the possibility of formally verified liveness of long-term resource leases in the face of dropped or failed packets, which is the domain of Chapter~9, and which all the cited approaches share as an open issue.

\section{Fault Classification Theory in Distributed and Cyber-Physical Systems}

Before a system can be designed to tolerate failures, its fault classification hierarchy must be established -- for while the terms are often conflated in day-to-day engineering discussion, precision is required in specifying what aspect of a system's behavior should be made tolerant. Avizienis, Laprie, Randell, and Landwehr define what is meant by the terms in the tripartite classification used for distributed and embedded systems: a fault is a situation that leads to an error, an error is a deviation from an expected internal state that may lead to failure if reached by the system's observable behaviors, and finally, a failure is an error that has manifested itself as some observable behavior beyond the normal range of the system specification \cite{avizienis2004basic}. A fault that does not manifest, or an error that is corrected before it can reach the system boundaries, is ultimately not a failure, which is the reason for implementing any redundancy-based reliability mechanisms proposed in this thesis.

Cristian's survey provides a useful categorization of fault manifestations according to their effects. A failure of a distributed algorithm is classified as a crash, omission, timing error, or arbitrary output based on the degree to which it can be distinguished from normal execution \cite{cristian1991understanding}. A crash failure leads to an immediate termination of a faulty process, while an omission failure causes it to omit some actions and respond incorrectly to some others; a timing failure makes the process execute correctly, but on incorrect time schedules; finally, an arbitrary failure results in a process producing any combination of responses, including those not dictated by the algorithm. The simplest type of failure in distributed computing is a failure to terminate, because any process in the system can distinguish this event as a fail-stop. This assumption is useful in defining fault-tolerant distributed algorithms, as the entire system can react to a fail-stop by terminating the failed process and recovering its state from backups \cite{cristian1991understanding}.

The Byzantine failure model is the most generic failure type, as arbitrary failures include crashes, omissions, and timing errors as special cases. Byzantine processes are capable of sending messages that contradict their own received messages or the received messages of other processes, effectively making communication unreliable \cite{lamport1982byzantine}. Solving consensus under the Byzantine assumption requires a consensus algorithm that can tolerate $f$ such failures among $N$ processes, which is only possible when $N \geq 3f + 1$, according to Lamport, Shostak, and Pease \cite{lamport1982byzantine}. For comparison, the 3-robot system analyzed in detail in Chapters~4 through~8 would be incapable of reaching consensus under these assumptions when $f = 1$ due to insufficient $N$. The reason for focusing on a more restricted fail-stop assumption, as opposed to designing solutions for Byzantine failures, becomes evident later in Chapter~6: the robots do not share a common clock, but instead rely on local control loops, making their broadcasts subject to tampering rather than mere termination.

The recent surveys on fault-tolerant cyber-physical systems expand on the tripartite fault classification framework, but introduce one additional distinction relevant to this thesis: the fault-tolerance pipeline. The process of tolerating faults is split between detection, diagnosis, and recovery. The first two, in particular, are subject to additional physical and time constraints beyond those imposed on traditional distributed systems \cite{piardi2020faulttolerance}. It is this additional level of detail that motivates the three-stage recovery framework described in Chapter~6.

\section{Multi-Robot Task Allocation: Foundational Taxonomies}

The allocation of a finite set of tasks among a team of robots so as to optimize some global metric is generally a scheduling problem that is in principle no different from any other resource-allocation scheduling problem in operations research. However, the ways this kind of problem has been approached in the literature bear sufficient differences across works that have classified the multi-robot task allocation (MRTA) problem along three independent axes \cite{gerkey2004formal}. First, whether robots are single-task (ST) or multi-task (MT): the former can only perform one task at a time while the latter are able to perform several simultaneously. Second, whether tasks are single-robot (SR) or multi-robot (MR): the former requires the exclusive use of one robot while the latter requires the collaboration of several robots. Third, whether allocation is instantaneous (IA) or time-extended (TA): the former happens at a particular point in time and is not revisited later while the latter deals with a series of allocations decisions over time that must be made with foresight. A problem that falls at the corner of the ST-SR-IA classification axis is trivially an instance of the assignment problem and can be optimally solved in polynomial time, while problems that fall elsewhere are more complex and may well be similar to vehicle routing or generalized assignment, for which no polynomial-time algorithms are known to exist.

While the earlier-described three-classification-axis system has a significant following in the field, more recent contributions offer a more fine-grained view. Korsah, Stentz, and Dias describe a four-axis system that builds on the first three by adding an additional consideration that some tasks have interrelated utilities to robots in ways that cannot be captured by the first three classification axes: in-schedule dependencies, where a robot's utility for a task is determined by the particular combination of tasks allocated to it, and cross-schedule dependencies, where a robot's utility for a task is determined by the combination of tasks allocated to other robots \cite{korsah2013comprehensive}. The battery proportional reallocation scheme described in this thesis's Chapter~6 is clearly an example of cross-schedule dependency: when a robot fails, the number of tasks that each surviving robot takes on is a function of the battery level of every other robot, not the failed robot's tasks in and of themselves. The four-classification-axis system adds considerably to the descriptive power of any MRTA analysis.

A survey of recent literature from 2013 to 2024 suggests that the field of multi-robot task allocation is broadly distributed across the three-classification-axis space, with no approach classifying as market-based, optimization-based, or lately learning-based, dominating the literature over the period \cite{athira2024systematic}. Different approaches to multi-robot task allocation continue to appear in the literature, each targeting slightly different regions of the three- or four-axis classification space. The heuristic sweep approach detailed in this thesis's Chapter~5 fits squarely within one particular ST-SR-IA allocation paradigm, with the ability for robots to temporarily escape their fixed allocation region if they are able to do so without draining their batteries, and fits within the broader category of solutions that have to make cross-schedule dependent allocation decisions as well. This is consistent with the discussion in Chapter~3 of this thesis: with regard to the comparison analysis of different approaches to MRTA, the sweep architecture allows making fewer allocation decisions by making more robots fixed to specific regions while reserving the option for robots to make allocation decisions at battery swap opportunities if needed.

\section{Statistical Pattern Recognition Foundations: Texture Descriptors, Margin Classifiers, and Ensemble Theory}

The edge-deployed anomaly classifier developed in Chapter~5 is built from five distinct methods, each of which was proposed in isolation some decades prior for unrelated applications; this section briefly covers the principles that each encodes, before they get combined into the final pipeline in Chapter~5.

Texture description starts with an observation that the patterns in a texture are captured not by the intensities of the pixels themselves, but rather their relationship to the intensities of their neighbors: Local Binary Pattern operator encodes this relationship into integers formed by bitwise comparison of the values of $P$ neighboring pixels to the value of the pixel in the center of the $P+1$-pixel window, yielding a bit string that is then interpreted as an integer,
\begin{equation}
LBP_{P,R}(x_c,y_c) = \sum_{p=0}^{P-1} s(g_p - g_c)\, 2^p, \qquad s(z) = \begin{cases} 1 & z \geq 0 \\ 0 & z < 0 \end{cases} \label{eq:lbp_general_definition}
\end{equation}
sampled over radius $R$. Ojala, Pietik\"{a}inen, and M\"{a}enp\"{a}\"{a} note that most of the information is already captured by patterns with at most two transitions from 0 to 1 or vice versa around the bit string, drastically reducing the number of bins from $2^P$ to $P+2$ while largely preserving diagnostic power; the resulting descriptor is invariant to monotonic transformations, including the common case of varying lighting conditions, and optionally rotation, under further post-processing \cite{ojala2002multiresolution}. Gradient-based descriptors take a related but different approach, capturing the direction and magnitude of intensity variations in a scene: Histograms of Orientated Gradients, proposed by Dalal and Triggs, encode gradient vectors' orientations in histograms computed over spatially local blocks, then normalized within each block to achieve better contrast invariance; the authors observe that such a combination of fine spatial resolution at a low level of detail (orientation bins) compared to conventional edge- and gradient-based feature descriptors at the time allows HoG descriptors to perform much better on a human detection task, an advantage quickly noticed across other computer vision applications \cite{dalal2005histograms}.

Combining the two types of texture features (LBP and HoG) into a feature vector results in a vector too large to be processed efficiently by a linear classifier with limited training data, requiring a dimensionality reduction step such as Principal Component Analysis. Its origin lies in Hotelling's 1933 paper finding that projections of correlated multidimensional data onto lower-dimensional subspaces spanned by the eigenvectors of the covariance matrix ordered by eigenvalue magnitude retain the maximum variance under the subspace transformation \cite{hotelling1933analysis}, with ``maximum variance'' replaced by ``minimum variance lost'' in the data's projection. In practice, this implies dropping the eigenvectors (principal components) corresponding to the lowest eigenvalues, an act that assumes the data does not contain any significant low-variance noise that may need to be filtered out, an assumption that cannot be validated by the procedure itself; a linear classifier learning on the reduced vector will be unable to distinguish between signals and noise that PCA projected onto lower variance directions.

The classification step itself takes the form of a linear Support Vector Machine, with several possible explanations for its selection; one of them was provided by Cortes and Vapnik in their 1995 paper on soft-margin classifiers, which described Maximum Margin classifiers' behavior when the classes were not fully linearly separable by introducing a slack variable penalized during training with a user-defined coefficient, allowing the SVM to make controlled classification errors on difficult points while maximizing the margin as a proxy for achieving generalization ability \cite{cortes1995support}. A more general justification comes from the statistical learning theory developed concurrently with SVMs' appearance: the margin of a linear classifier provides an upper bound on the expected generalization error, independent of the feature space's dimensionality, which makes Max Margin SVMs linear classifiers with the best-tightened generalization error bound, directly applicable to any linear method, including PCA projection.

Finally, a classification pipeline of ensemble classifiers was selected over one dominant classifier because of their combined ability to create highly accurate prediction models from many weak classifiers, often easier to tune and less error-prone. Boosting algorithms, such as AdaBoost proposed by Freund and Schapire, are iterative, training an ensemble of weak classifiers in sequence by reweighting the training instances based on the previous ensemble members' errors so that subsequent ones focus more attention and computational resources on the more challenging examples; when such an algorithm is given enough iterations and relatively accurate weak classifiers to work with, its training error asymptotically approaches zero at an exponential rate, a property formally proved by Schapire and Freund for AdaBoost's specific boosting scheme \cite{freund1997decisiontheoretic}. Gradient boosted trees, such as the XGBoost library used for the analytical redundancy task in Chapter~6, are an evolution of gradient descent optimization adapted for tree-structured models, a type of ensemble learning algorithm where each subsequent model is trained not on modified instances but on the gradients of the loss function, iteratively correcting the prediction errors of the previous models. Similarly, bagging procedures such as Random Forests train independent models using independent subsets of instances and combine them via a weighted voting stage; however, they do not focus on the noisy or difficult examples in the same way boosting does; in a survey of the differences between the two approaches, the choice between them was said to depend on circumstances and data as the relative advantage of one method over the other was unclear empirically and theoretically \cite{mienye2022survey}.

\section{Explainable AI: Theoretical Taxonomy of Model Interpretability}

A classifier's accuracy is a measure of how often it reaches a correct decision, but does not comment on why a decision of a particular instance was reached. Its increasing use in domains where decisions are not easily subject to human-level scrutiny, and especially the use of models too complex to be directly interpreted by hand -- the linear SVM of Section~2.9 already qualifies as barely interpretable -- has motivated extensive discussion on how to retrieve an explanation of such a model's decision post-factum. Arrieta et al.\ classify the literature on post-hoc explanation methods according to two broad criteria \cite{arrieta2020explainable}. The first distinguishes between transparent (or intrinsically interpretable) models, which can be ``understood'' directly, and opaque models, which require additional analysis. The second criterion is orthogonal to the first: it differentiates between model-specific methods, which use knowledge of the structure of the classifier being explained, and model-agnostic ones, which do not require such knowledge and instead only treat the classifier as a black box, receiving inputs and observing outputs.

The latter, post-hoc model-agnostic methods, comprise the most common category in the applied literature, as they do not restrict the user to a predefined set of explanation algorithms. Ribeiro et al.'s LIME falls into this category: it approximates the behavior of an arbitrary classifier by training an intrinsically interpretable model (typically, a sparse linear regressor) on a small random sample around the decision boundary, finding a human-readable explanation that locally approximates the behavior of the larger and more complex classifier around a decision \cite{ribeiro2016why}. This focus on local explanations as opposed to global ones -- explaining individual decisions as opposed to the classifier's behavior overall -- comprises a third categorization axis. Explanation methods can be categorized by whether they explain individual prediction decisions, or attempt to capture the behavior of the classifier across its entire input space, and these two approaches often have very different computational costs.

An alternative to local, model-agnostic explanations is to use global, model-specific explanations. This requires the existence of a transparent classifier to begin with, which is not always the case. Local explanations via LIME-style approximation work best when the input space is low-dimensional -- or more accurately, when the input features have low dimensionality and originate from a source with known spatial or semantic structure, as discussed in Section~2.1. A linear SVM trained on these kinds of features (e.g., texture statistics from localized regions of an image) would itself constitute a transparent classifier, however. Other features, such as holistic image representations, would benefit from a different approach to explanation that works directly with the input pixels without requiring additional sampling steps, which is the approach this thesis takes in Chapter~6. A brief overview of the current state of the art in the domain of post-hoc explanation methods can be found in Section~4.1, which discusses recent work by Alvarez-Melis et al.\ on evaluation of explanation quality -- one of the few aspects of the machine learning lifecycle that was not standardized in the wake of the post-hoc explanation literature explosion \cite{saeed2023explainable}.

This lack of a standardized evaluation procedure is the context in which the fallback classifier's lack of an equivalent explanation mechanism should be understood later in this thesis: a similar problem is not specific to the fallback classification literature \cite{myllyaho2022misbehaviour}.
